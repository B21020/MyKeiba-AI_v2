## 問題意識

### 現行戦略の課題
1. **z-score 閾値 ≥ 3.136 は厳しすぎる**: 56レース中わずか1頭のみ閾値突破 (マルディランダ, 16着ハズレ)
2. **ベット機会の極端な少なさ**: テスト期間全体でも n=66 — 実戦での「待ち」が長すぎる
3. **統計的有意性に未到達**: P(RR<1)=0.298 — 偶然と区別できない

### 2/14-15 の予備分析で見えたパターン
- `rank≤3 & 人気≤3`: **62.9%的中, 複勝RR=96.0%** (56レース, n=62)
- `rank≤2 & 人気≤4`: **60.0%的中, 複勝RR=94.2%** (n=55)
- モデルフィルタ効果: 人気≤3 全体の RR=81.0% → rank≤3 でフィルタすると **RR=96.0%** (+15.0pp)
- モデルが除外した人気馬 (rank>3): RR=72.2% — **モデルは「来ない人気馬」を弾く能力がある**

→ 閾値ベースからrank×人気ベースへの戦略転換の可能性を長期バックテストで検証

## P15 計画: score_rank × 人気 交差条件の長期バックテスト

### 目的
1. 「score_rank × 人気」の交差条件が長期的に安定した複勝RRを生むか検証
2. 最適な (max_rank, max_pop) ペアを特定
3. z-score 閾値ベース vs rank×人気ベースの優劣を評価
4. Bootstrap CI で統計的有意性を検定

### テスト期間
- **P11-ext と同一条件**: 2020-2026 全データ、test_size=0.15
- テスト期間: 2022-09-25 ~ 2026-02-01 (11,460レース, 158,052行)
- モデル: P11-ext best params (pos-perm 145 cols, num_leaves=127, max_depth=6, lr=0.111)

### 検証条件（グリッドサーチ）

#### A. score_rank × 人気 交差条件（メイン）

`score_rank` はレース内 z-score 順位、`人気` は単勝オッズから rank(method='min') で導出 (99.2%精度)。

| max_rank | max_pop 範囲 | 条件数 |
|----------|-------------|--------|
| 1 | 1, 2, 3, 4, 5, 6, 7, 8 | 8 |
| 2 | 1, 2, 3, 4, 5, 6, 7, 8 | 8 |
| 3 | 1, 2, 3, 4, 5, 6, 7, 8 | 8 |
| 4 | 1, 2, 3, 4, 5 | 5 |
| 5 | 1, 2, 3, 4, 5 | 5 |

計 **34条件**

追加で確認する複合条件（穴馬パターン）:

| 条件 | 意図 |
|------|------|
| rank≤3 & 人気≥4 | モデル高評価 × 人気薄 (value bet) |
| rank≤2 & 人気≥5 | 穴馬パターン (高配当狙い) |
| rank=1 & 人気≥4 | 最高スコア穴馬 |

計 **37条件**

#### B. z-score 閾値条件（比較用ベースライン）

既存 P11-ext の「z-score ≥ threshold」も同時に再評価:

| z-score threshold | 備考 |
|-------------------|------|
| 2.0, 2.2, 2.4, 2.6, 2.8, 3.0, 3.136, 3.4 | 8段階 |

z-score 閾値版に max_bets_per_race=3 制約あり/なしの2パターン = **16条件**

#### C. ハイブリッド条件（rank × 人気 + z-score 下限）

rank×人気のフィルタに加えて z-score の下限を設定:

| rank | 人気 | z-score下限 | 意図 |
|------|------|------------|------|
| ≤3 | ≤3 | ≥1.0 | 低スコアを除外 |
| ≤3 | ≤3 | ≥1.5 | 中程度以上に限定 |
| ≤2 | ≤3 | ≥1.0 | rank×人気強化 |
| ≤2 | ≤4 | ≥1.0 | 人気緩和+z-score制約 |

計 **4条件**

**合計: 57条件**

### 評価指標

各条件ごとに算出:

| 指標 | 説明 |
|------|------|
| n_bets | 総ベット数 |
| n_races | ベットしたレース数 |
| hit_rate | 複勝的中率 |
| return_rate (RR) | 回収率 (return / investment) |
| profit | 投資対比利益 |
| 95% CI | Bootstrap CI (レース単位, 10,000回) |
| P(RR<1) | Bootstrap分布で RR<1 の割合 |
| profit_months | 月別利益月の割合 |

### Score計算方法

2パターンで score_rank を算出:

1. **Raw score rank**: `predict_proba` の出力をそのまま使い、レース内順位を付ける
2. **Z-score rank**: レース内 z-score 化してから順位を付ける

→ 理論的にはレース内順位は同一になるはずだが、z-score の下限フィルタ (Section C) では挙動が異なるため両方保持。

### 実装方針

スクリプト: `tools/run_p15_rank_pop_backtest.py`

```
使用法:
  python tools/run_p15_rank_pop_backtest.py [--out-dir models/YYYYMMDD/p15]

処理フロー:
  1. P11-ext best params で学習 (既存インフラ流用)
     - featured_data → DataSplitter(test_size=0.15)
     - train_without_tuning()
  2. テストデータ予測 → score_table 生成
  3. score_rank, 人気(単勝オッズ由来) を付与
  4. 37+16+4=57 条件でグリッドサーチ
     - 各条件: 対象馬をフィルタ → BetPolicyFukusho 相当のロジックで賭算出
     - Simulator.calc_returns() で RR 計算
  5. 有望条件 (top-5) で Bootstrap CI (10,000回)
  6. 月別/場別ブレークダウン
  7. 結果CSV + レポート出力
```

### 技術的な注意点

1. **人気の導出**: `test_data['単勝']` からレース内ランク → 人気。NaN は除外（5,043行 / 158,052行 = 3.2%）
2. **score_rank の定義**: レース内の score 降順ランク (1 = 最高スコア)
3. **複勝判定**: `Simulator.calc_returns()` を流用。既存の return_tables.pickle とのマッチングは race_id (文字列) キー
4. **Bootstrap**: レース単位リサンプリング (11,460レース × 10,000回)。計算量は大きいので有望条件のみ実行
5. **多重比較**: 57条件を試すため偽陽性リスクあり。Bonferroni補正 (α=0.05/57≈0.0009) も参考表示

### 期待される成果

| シナリオ | 結果 | アクション |
|---------|------|----------|
| rank×人気条件で RR>1.0 & P(RR<1)<0.3 | 有望 | 本番戦略として採用候補 |
| rank×人気条件で RR>1.0 & P(RR<1)<0.1 | 統計的に有意に近い | 本番戦略として強く推奨 |
| rank×人気条件で RR≤1.0 | z-score閾値と同等 or 劣る | 現行P11-ext維持 |
| 穴馬パターンで高RR | value bet戦略候補 | 追加検証 |
