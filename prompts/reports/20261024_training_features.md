# 調教データ（坂路・ウッドチップ）は発走6分前の市場に情報を足すか

対象：市場が持っていない種類の情報の検証。前提は [段階2の再比較（6分前の市場）](20261024_stage2_t6.md)。実施日：2026年10月24日。

## 結論

**調教データの特徴量を足しても、発走6分前の市場に対する上積みは見られなかった。** 調教変数をまとめて足すと、外側3期間の合計で ΔR² −0.0027（95%区間 −0.0050〜−0.0006）とむしろ悪化した。1変数ずつ足した探索的な確認でも、区間が0を上回る変数は無かった。2か月（約520レース）で推定する係数が期間ごとに符号を変え、その推定のぶれが損失になっている。

市場（6分前）にどれだけ情報が足りないかという問いに対して、手元で取れる公開情報（過去成績・通過順・条件別成績・騎手・走破能力指数・ID系・調教）のどれからも、上積みは検出できなかった。

## データの取得（JV-Link、お試し期間）

| 項目 | 内容 |
|---|---|
| 種類 | 坂路調教（SLOP／HCレコード、60バイト）、ウッドチップ調教（WOOD／WCレコード、105バイト）。SDK 5.0.0 の仕様書・構造体定義に合わせて読む（`modules/preparing/_jv_training.py`） |
| 取得方法 | 通常データ（JVOpen の option=1）を1週間ずつ。初回だけ「ご注意事項」の確認窓が出て、ユーザーが内容を確認して進めた |
| 提供範囲 | 通常データは**直近約1年**（2025年10月21日〜）。それより前（2025年10月18日以前）は「該当データなし」 |
| 過去分（セットアップ） | option=4 は初回に取得元の選択窓が出たあと、**-301（認証エラー）**。お試し期間・利用キーなしでは過去分を取れない |
| 取得結果 | 坂路 553,069件、ウッドチップ 162,301件（2025-10-21〜2026-10-24）。解析エラー0。完全一致の重複（週の境目）は特徴量の作成時に除いた |
| 仕様上の提供開始 | 坂路は2003年以降、ウッドチップは美浦2021年7月27日・栗東2021年12月7日以降（JV-Data 仕様書）。有料の利用キーがあればセットアップで取れる見込み（未確認） |

取得のスクリプト：`tools/jvlink_fetch_training.py`。データは git 対象外の `data/jv_training/`。

## 特徴量（`modules/preprocessing/_training_features.py`）

- 速さは、同じトレセン・同じ日（ウッドは同じコースも）の中の z を符号反転したもの（速いほど正）。その日の馬場の影響を除くため。
- 予測するレースの**日付より前**（当日を含まない）14日以内の調教だけを使う（テストで確認）。
- 変数：坂路の14日内最速、坂路の直近の最後1ハロンの速さ、ウッドの直近の速さ、ウッドの直近の最後1ハロンの速さ、坂路・ウッドの有無、14日内の本数（log）。
- 外側期間の出走馬のうち、14日以内に調教記録がある割合は93〜99%（坂路88〜93%、ウッド67〜74%）。血統登録番号はそのまま馬IDとして結び付いた。

## 比較の方法

調教データは2025年10月21日以降しか無いので、能力モデル（2021年〜で学習）の入力にはできない。Benter の第2段と同じく、レース内の条件付きロジットに変数として足した。

- M0：log 発走6分前の市場確率
- M1：M0＋log 能力モデル（base：過去着順＋通過順＋条件別成績＋騎手成績）
- M2：M1＋調教変数（7個）
- M3：M0＋調教変数（7個）
- 1変数ずつ（探索的）：M0＋各調教変数

fold は [6分前の市場での比較](20261024_stage2_t6.md) の3つ（2か月で推定 → 次の2か月で評価。評価は2026年1〜2月・3〜4月・5〜6月、計1,580レース）。最終確認期間（2026年7月以降）のレースは読んでいない。スクリプト：`tools/run_training_features_eval.py`、出力：`models/20261024/training_features/results.json`。

## 結果（ΔR²、レース単位の対の再標本化による95%区間）

| 比較 | 1〜2月 | 3〜4月 | 5〜6月 | 合計 |
|---|---:|---:|---:|---|
| M2（市場＋能力＋調教）− M1（市場＋能力） | −0.00420 | −0.00190 | −0.00211 | **−0.00272（−0.00502〜−0.00057）** |
| M3（市場＋調教）− M0（市場） | −0.00410 | −0.00192 | −0.00210 | **−0.00270（−0.00498〜−0.00056）** |
| M1（市場＋能力）− M0（市場） | +0.00003 | −0.00024 | +0.00020 | −0.00000（−0.00051〜+0.00050） |

1変数ずつ足した探索的な確認（合計、M0 との差）：

| 変数 | ΔR² | 95%区間 |
|---|---:|---|
| 坂路の14日内最速 | −0.00249 | −0.00405〜−0.00094 |
| 坂路の直近の最後1ハロン | −0.00003 | −0.00021〜+0.00018 |
| ウッドの直近の速さ | −0.00012 | −0.00048〜+0.00025 |
| ウッドの直近の最後1ハロン | +0.00009 | −0.00060〜+0.00076 |
| 坂路の有無 | −0.00024 | −0.00146〜+0.00095 |
| ウッドの有無 | −0.00039 | −0.00109〜+0.00024 |
| 14日内の本数（log） | +0.00045 | −0.00058〜+0.00151 |

坂路の14日内最速の係数は、期間ごとに +0.115・−0.066・+0.173 と符号が変わった。係数が実際には0に近いのに、2か月の推定で ±0.15 程度の値が付くと、評価期間ではその分だけ確率がずれて損失になる。ウッドの直近の最後1ハロンは、まとめて足したモデル（M3）では3期間とも正の係数（+0.19〜+0.26）だったが、1変数では区間が0をまたぐ。結果を見てから選んだ変数になるため、最終確認の候補にはしない。

## 読み方と限界

- 調教タイムも、競馬新聞や JRA-VAN で広く公開されている。市場に既に織り込まれているという解釈と矛盾しない。
- 推定期間が2か月と短く、係数のぶれが大きい。調教データの過去分（有料のセットアップ）があれば、能力モデルの入力として長い期間で学習でき、結論が変わる可能性は残る。
- 速さの z は、坂路の軽めの調整（4ハロン65秒前後が中央値）と本格的な追い切りを区別していない。追い切りだけを選ぶ（例：同じ週の最速、ラップの加速）作り方は未検証。

## 再実行

```powershell
.\.venv\Scripts\python.exe tools\jvlink_fetch_training.py --spec SLOP WOOD --start 2025-10-11 --end 2026-10-25 --chunk-days 7 --out data\jv_training
.\.venv\Scripts\python.exe tools\run_training_features_eval.py --out models\20261024\training_features
```

取得は約5分（週ごと111回の要求）、比較は約30秒。テスト：`tests/test_training_features.py`（レコードの位置、レース当日を含まないこと、14日の窓）。
