## 取得元の選択

ユーザーの回答は「JRA-VAN Data Lab.未契約」。読み取りだけの環境点検でもJV-LinkのCOM登録・導入情報は見つからなかった。Pythonは64bitでpywin32は利用可能だが、JV-Linkでの実取得が可能な環境ではない。

当面はnetkeibaの一般公開オッズ画面と、その画面が参照する匿名の取得先を使う。認証情報・有料会員向けパラメータは使わず、単発・逐次取得とする。HTTPエラーで停止し、自動再試行は行わない。ページ取得から価格取得まで最低1.2秒空ける。通常表示の価格を取得できたことは、今後の更新頻度や継続提供を保証しない。

JRA-VANの将来の選択肢として、公式SDKの構造とO1形式の読み込み処理も準備した。公式SDKは参照用にダウンロードしただけで、契約・試用申込・インストーラー実行は行っていない。利用キーをコードやチャットに保存する処理もない。

公式仕様で確認できた範囲は次のとおり。

| 確認事項 | 結果・根拠 |

| 時系列の取得口 | 0B41。提供期間は直近1年間。[JV-Data仕様書 p.52・56](https://jra-van.jp/dlb/sdv/sdk/JV-Data4901.pdf#page=56) |
| 単勝・複勝 | O1レコードに単勝と複勝の下限・上限がある。[JV-Data仕様書 p.15](https://jra-van.jp/dlb/sdv/sdk/JV-Data4901.pdf#page=15) |

| 接続・読み取りの呼出し | JVInit、JVRTOpen、JVGets、JVClose。[JV-Linkインターフェース仕様書](https://jra-van.jp/dlb/sdv/sdk/JV-Link4901.pdf) |

仕様上の提供期間と、実際に全対象の履歴が取れるかは別に扱う。今回はJV-Link接続を実行していない。

## 実際に保存できたデータ

[公開オッズ画面](https://race.netkeiba.com/odds/index.html?race_id=202608040911)で確認した菊花賞を対象にした。対象IDは開催一覧から確認した。

| 項目 | 保存値 |
|---|---|
| race_id | `202608040911` |
| 発走予定 | 2026-10-25 15:40:00 |
| 発走予定を観測した時刻 | 2026-10-23 22:46:53.611008 |
| 配信元の表示時刻 | 2026-10-23 22:35:23 |
| 実際の価格取得時刻 | 2026-10-23 22:46:55.377713 |
| 価格の件数 | 18頭分の単勝、複勝下限・上限、各人気 |
| 表示時刻からの経過 | 692.377713秒（約11分32秒） |
| 記録件数 | snapshots 1、quotes 18、schedules 1、decisions 0 |

配信元の時刻は日本時間と解釈して保存し、実際の観測時刻とは別の列にした。暫定の鮮度上限は600秒であり、**この価格は判断用の選択時に `Latest eligible snapshot is stale` として除外される**。記録の成功に合わせて鮮度上限を緩めてはいない。遅延が通常の配信間隔・キャッシュ等のどれによるかは未確定で、開催中の適切な時点で確認する必要がある。

予測や購入判断は実行していない。モデル版・特徴量版・判断理由の保存テーブルは用意したが、実在する予測を接続するまで空にしておく。発売条件・取消／除外フラグは公開価格だけから確定できないため、不明として保存している。

## 実装した保存・選択規則

- 取得元、実取得か過去履歴の取り込みか、配信元の時刻、観測時刻を分離する。異なる取得元の価格を黙って混ぜない。
- 実取得モードでは、配信元時刻・観測時刻の両方が判断時刻以前のものだけを選ぶ。過去履歴モードは後日取り込んだ資料であり、当時観測できた証明とは扱わない。
- 確定価格・予想価格は途中オッズとして採用しない。レースID不一致、将来の表示時刻、時差指定のない時刻、既知の発走後の公開価格取得は拒否する。
- 1つのスナップショット全体を採用し、取消・欠損馬の価格を古いスナップショットで埋めない。同一表示時刻の訂正も、実際に取得できた時点以降だけで利用する。
- 公開取得先の人気順データは、順位のキーではなく応答中の馬番で対応付ける。JSONPは決まった形式を検査してJSONとして読み込み、コードとして実行しない。
- 取得応答とページ原文をSHA-256付きで保存する。同じ内容の再保存は価格を重複させず、観測履歴を残す。発走予定の各観測は別行で保持する。

ソース・テストはリポジトリ内、取得データはgit対象外の `data/odds/` に保存する。

| パス（リポジトリ直下から） | 内容 |

PowerShellでリポジトリ直下から実行する。公開取得は実行した時点の1回だけであり、過去時刻に戻した取得はできない。以下のレースは発走前だけ実行可能。

```powershell
.\.venv\Scripts\python.exe tools\capture_public_odds.py --race-id 202608040911
```

保存した公開価格を、判断時刻の情報だけで選ぶ例。初回データに対するこのコマンドは、上記の鮮度不足を理由に停止するのが正しい動作。

```powershell
.\.venv\Scripts\python.exe tools\odds_snapshots.py select --race-id 202608040911 --decision-at '2026-10-23T22:46:55.377713+09:00' --mode live --source netkeiba_public
```

JV-Linkの取得処理は未実機検証。契約・公式設定が済む場合でも、最初は1レースの試験で提供範囲・時刻・取消情報を照合する。今回の未契約環境では実行しない。

## 検証と残作業

オフラインの関連テストは26件通過した。内訳は4.2更新処理8件、共通オッズ処理12件、公開オッズ処理6件。時刻制約、鮮度、取得元の分離、複勝上下限、人気順応答の馬番対応、訂正価格の到着時刻、取消馬の古い価格への差し戻し防止を含む。合成データのテストと、実際の公開価格1回の取得確認は区別する。

4.3の残作業は次の順で進める。

1. 発走前の適切な時点で配信の鮮度・更新間隔を確認し、判断時刻と許容する価格の古さを固定する。必要な価格がなければ判断を見送る。
2. 予定発走5分前の収集手順を整え、発走変更・取消／除外の時刻付き情報を照合する。現時点では常駐処理・定期実行を開始していない。
3. 評価基盤を整えたモデルから、特徴量版・モデル版・予測確率・判断理由を価格IDに結び付けて記録する。
4. 同じ対象の確定結果・払戻が揃ってから、判断時点版と確定価格版の差を測定する。必要な時系列価格がない過去期間は、確定オッズを使う参考評価と明記する。

当面の公開ページによる前向きの記録では、2026年2月〜10月の過去時系列価格を復元できない。今回の準備だけで回収率の評価が改善したとは結論しない。
