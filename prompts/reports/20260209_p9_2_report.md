## 1. 実験概要

### 目的
P9-1 の n_bets=51 問題を解決するため、Optuna objective に：
1. **min_bets_obj=200**: validation で bet 数 ≥ 200 を強制
2. **objective=profit**: `(RR-1) × n_bets` を最大化 → bet 数増加インセンティブ

### 仮説
- Profit objective により HPO が「RR=1.05, n=300」のようなバランス解を見つける
- n≥200 なら Bootstrap CI が狭まり、RR=1.05 程度で統計的有意性を達成可能

### 設定
| パラメータ | P9-1 | P9-2 |
|---|---|---|
| Optuna trials | 150 | 150 |
| Objective | **RR** | **profit = (RR-1)×n_bets** |
| min_bets_obj | 30 | **200** |
| Bootstrap | 2,000 | 2,000 |
| featured_data | rel_ext (342cols) | rel_ext (342cols) |
| テスト期間 | 2024-07 ~ 2026-02 | 2024-07 ~ 2026-02 |

### コード修正 (今セッション)
1. `best_val = 0.0` → `best_val = -float("inf")` — 負の profit を Optuna に返却可能に
2. `any_valid` フラグ追加 — min_bets を満たす閾値が無い場合 `-999.0` を返却
3. `bootstrap_fukusho_ci` の early return に全キーを追加 (n_bets=0 時の KeyError 修正)

### 致命的知見: n≥200 では統計的に有意な「損失」

- th=3.579 (n=207): P(RR<1)=0.955 → **RR < 1.0 が 95.5% 確実**
- → **このモデルは 200+ bets では確率的に損をする**
- → n=54 での RR≈1.06 は **テール部分のノイズ/運** の可能性が高い

### 根本的課題
1. **エッジが閾値極端部にしか存在しない**: RR>1.0 は z≥3.7 (上位0.4%) でのみ達成可能
2. **中程度 bet 数では確実に損失**: n≥200 では P(RR<1)≥0.955 → 有意な損失
3. **HPO objective 切替だけでは不十分**: 本質的にモデルが生むスコアの質に依存
4. **2025-03 / 中京依存**: 全利益が特定月・特定場に集中 → 再現性に疑問

### 推奨 Next Actions
1. **P9-3/P9-4 は慎重に**: objective 変更だけでは構造的問題は解決しない
2. **P10: 特徴量エンジニアリング** を優先検討 — 現行342特徴量で生成可能なエッジに限界
3. **別市場検討**: 複勝ではなくワイド・馬連など異なる券種への展開
4. **overfitting 対策**: min_split_gain の下限引き上げ、num_leaves 上限引き下げ
