## 方針

方針を「市場で公開された情報から回収率100%以上」から「ほどよく機械学習して、ほどよく競馬を楽しむための意思決定の補助」に変えた（2026年11月1日、ユーザーの決定）。

理由：判断時刻（発走4分前・6分前の配信）の市場を超える情報は、次のどの検証でも見つからなかった:
- 能力モデル
- 走破能力指数
- 調教
- オッズの動き
- 票数
- 馬連

唯一の手がかり（複勝の食い違い）は、お金を使わずに前向きに記録し続ける（紙上の検証）。

## 使い方

| やること | コマンド |
|---|---|
| 開催日に動かす（毎週土日 9:30 に自動、タスク登録後） | `.venv/Scripts/python.exe tools/decision_aid/live.py run --date yyyymmdd` |
| ページを見る | ブラウザで http://127.0.0.1:8765 （自分のPCだけ） |
| 記録だけ見る（開催日以外） | `.venv/Scripts/python.exe tools/decision_aid/live.py serve --date yyyymmdd` |
| 精算を手でやり直す | `.venv/Scripts/python.exe tools/decision_aid/settle.py --date yyyymmdd` |
| 累計の成績 | `.venv/Scripts/python.exe tools/decision_aid/report.py` |

開催日の動作:
- 各レースを、発走15分前〜2分後に20秒ごとに JV-Link（0B41）で読む。
- 6分前の配信を受け取った時点で、数字を計算して記録する。
- 最終レースの約30分後に、結果ページ（netkeiba、1レース1回）から複勝の払戻を取って精算する。
- 記録は `data/decision_aid/`（git 対象外。JRA-VAN のデータを含む）。

## ページに出るもの

- **今日のレース一覧**：状態（待ち／数字あり／見送り／確定）と、紙上の検証の対象数。
- **各レースの表**（発走6分前のオッズから）:
  - 各馬の単勝・複勝オッズ、人気
  - 勝つ確率・複勝圏の確率（固定した補正）
  - 100円あたりの平均の戻り（単勝は確率 × オッズ、複勝は確率 × 下限）
  - 紙上の検証の対象（●）
  - 発走までと、判断（発走4分前）までの残り時間
- **紙上の検証の成績**：今日と累計（購入数、的中、回収率、開催日単位の95%区間）。開発期間の結果と並べる。
- **券種と人気ごとの平均の戻り**：開発期間に全部買った場合の実績。

人気別の平均の戻り（100円あたり）:

| 6分前の人気 | 単勝 | 複勝 |
|---|---|---|
| 1 | 73円 | 85円 |
| 2 | 78円 | 82円 |
| 3 | 71円 | 80円 |
| 4〜5 | 77円 | 77円 |
| 6〜8 | 84円 | 73円 |
| 9〜12 | 69円 | 65円 |
| 13〜18 | 68円 | 58円 |

馬連は、1番人気の組が71円、61番人気以下の組が49円。

文言は補助に徹し、購入を勧める表現は使わない。補正した単勝の「平均の戻り」は、どの馬もほぼ77〜80円になる。補正が市場とほぼ同じ（β = 1.005）ためで、「単勝は人気による差が小さく、券種の払戻率（80%）がそのまま損になる」ことを示している。

## 固定した規則（`reproducibility/20261101_decision_aid/frozen_rule.json`）

規則のハッシュ：`62e820a1edd63761bd15d77c7313991dcc6866ea6bfe43d4791325e932cbab60`。ファイルを書き換えると、ハッシュが合わず使えなくなる。

| 項目 | 値 |
|---|---|
| データ | 開発期間 2025-11〜2026-06、評価対象の2,110レース・30,002頭（最終確認期間は読んでいない） |
| 判断に使う配信 | 発表が発走5分前以前の最新（6分前の配信） |
| 勝つ確率 | レース内 softmax(β · log q6)、β = 1.005 |
| 複勝圏の確率 | sigmoid(−0.099 + 0.898 × logit(Harville の複勝の確率)) |
| 紙上の検証 | 複勝圏の確率 × 6分前の複勝オッズの下限 ≥ 1.00 の馬に、複勝100円 |
| 見送り | 発走4分前までに6分前の配信を受け取れなければ買わない |
| 1回だけ | 判断はレースごとに1回。同じレースの2回目の判断は記録を拒否する |

## 確認したこと

- **テスト**（`tests/test_decision_aid.py`、7件。既存と合わせて73件、すべて通る）:
  - 規則の書き換えの検出
  - 確率の合計（勝つ確率は1、複勝圏は約3）
  - 1分前の配信を使わないこと
  - 発走4分前より後の受け取りが見送りになること
  - 同じレースの2回目の判断の拒否
  - 精算（払戻・返還）
  - ページの JSON の形
- **過去データでの再生**：2026年1〜6月の全開催日を、保存済みの0B41原文で再生した。受け取りは発表の100秒後とみなし、別のデータベースに書いた。
  - 1,722レースを判断し、7レースは配信が無く見送り。紙上の対象は131頭。
  - 開発期間の分析（H・1.00、141頭）との一致は109頭。違いは、補正を期間ごとではなく全期間で1回に固定したことと、評価対象外のレースも含むことによる。
  - 保存済みの払戻で精算すると、131件・的中37件・回収率142%（区間 39〜309%）、上位3回を除くと50%。開発期間の分析（140%）とほぼ同じ。補正をこの期間で推定しているので、楽観的な値。
- **ページ**：再生したデータでページを開き、レース一覧・表・成績・参考の表の表示と、レースの切り替えを確かめた。

## 評価の時点（事前に決めたもの）

- 3か月ごとに途中報告（`report.py`）。
- **1年または300件で判定する。** 回収率の95%区間（開催日単位）の下限が100%を上回らない限り、お金を使う運用には進まない。
- 参考：開発期間のペースは6か月で約130件。300件に届くまで1年強かかる。
